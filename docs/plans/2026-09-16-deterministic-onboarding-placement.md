# Deterministic onboarding and placement checks

## Problem

Setup options were generated by the LLM, but profile persistence accepts a small canonical vocabulary. A label such as `30 min` or an invented level could therefore render as selectable and then fail at `/profile`. Self-reported Intermediate and Advanced levels also had no evidence check.

## Design

- `/api/topics/:id/setup-questions` returns two server-owned questions with stable IDs and canonical `{ value, label }` options. The endpoint does not call an LLM.
- The client normalizes legacy string responses as a compatibility boundary and never submits a model-invented value.
- Beginner profiles proceed directly to curriculum generation.
- Intermediate and Advanced profiles call `POST /placement/start`. The server validates and stores a five-question assessment containing both multiple-choice and objective questions. Answer keys and objective rubrics remain server-side.
- `POST /placement/submit` validates the stored question IDs, answer types, and lengths before asking the selected provider to evaluate. It commits the result only after a finite 0–100 score is returned. Repeated submits of a completed attempt are idempotent.
- Verification thresholds are deterministic: Intermediate requires 70; Advanced requires 85, with scores between 65 and 84 recommending Intermediate and lower scores recommending Beginner.
- `/profile` requires a completed matching assessment for every non-Beginner self-report and stores the verified level as `topics.level`. A provider failure or malformed response leaves the profile unchanged.
- Placement attempts are included in exports; imports treat the new table as optional so older backups still restore.

## User flow

The placement check is a setup sub-step, so the existing four-stage onboarding indicator and curriculum confirmation flow remain unchanged. The result explains the score and recommended starting level, then lets the learner continue or retry with a fresh assessment.

## Validation

Focused curriculum, backup, onboarding, and normalization tests cover canonical values, legacy aliases, malformed setup responses, assessment gating, mixed question types, idempotent completed submissions, and verified-profile persistence.
